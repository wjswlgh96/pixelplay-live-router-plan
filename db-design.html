라이브 MVP와 후원 플로우를 위한 Supabase DB 확정 초안입니다.

현재 public 스키마의 user, chat_room, chat_room_member, message는 유지하고, 라이브 방송·후원·투표·팔로우·규칙 동의는 별도 도메인 테이블과 RPC 경계로 분리합니다. 이 문서는 GitHub dev 브랜치 최신 fetch와 Supabase MCP로 확인한 원격 DB 기준을 우선 반영합니다.

일반 채팅방은 기존 구조를 유지합니다. 라이브 채팅은 공개 읽기, 비로그인 시청, 방송 회차 통계가 필요하므로 별도 테이블로 분리합니다.

기존 채팅 애플리케이션 도메인은 유지하고, 라이브 MVP만 새 도메인으로 확장합니다.

설계 원칙

planning MVP와 실제 project RPC convention을 같이 맞춘 기준입니다.

  • 별도 creator_channel 테이블은 만들지 않습니다. MVP는 1유저 1라이브 채널이므로 /live/[creatorId]의 creatorId는 public.user.id를 그대로 사용합니다.
  • 설정과 방송 회차는 분리합니다. creator_studio_setting은 크리에이터당 1개 row를 계속 update하고, live_broadcast는 방송을 켤 때마다 새 row를 생성합니다.
  • 현재 방송 여부는 상태 enum이 아니라 ended_at is null로 판단합니다. 공개/비공개 방송 기능은 MVP에서 제거했으므로 live_visibility도 만들지 않습니다.
  • 라이브 목록은 JSON snapshot RPC 계약으로 관리합니다. get_live_list는 필터, 정렬, 검색어, Hero 제외 ID를 받아 items, totalCount, hasMore를 반환하고 팔로잉 판정은 auth.uid() 기준으로 계산합니다.
  • 일반 채팅과 라이브 채팅은 분리합니다. 일반 메시지는 message, 라이브 채팅과 클린봇 결과는 live_message에 저장합니다.
  • 팔로우와 채팅 규칙 동의는 같은 관계 테이블에 둡니다. viewer_creator_relation은 팔로우 여부, 팔로우 시각, 채팅 규칙 동의 버전을 같이 관리합니다.
  • 후원은 지갑 원장과 방송 후원 이벤트를 나눕니다. 금액 정합성은 wallet_transaction이 담당하고, 방송 화면과 크리에이터 수익 내역은 donation이 담당합니다.
  • OBS Alert 템플릿은 DB에 저장하지 않습니다. MVP는 고정 템플릿이므로 DB에는 표시 시간, 사운드 프리셋 키, 볼륨, TTS 설정, 채팅 후원 메시지 표시 여부, URL 버전만 저장합니다.
  • 실제 정산 인증은 MVP DB 범위에서 제외합니다. 정산 화면용 후원 내역 RPC는 존재하지만, 실명조회와 계좌 인증은 후속 확장으로 둡니다.

Toss 결제 API 설계

Toss Payments는 MVP 결제사로 확정하고, 클라이언트 결제창과 서버 원장 반영을 분리합니다.

라우터입력서버 책임DB 반영
/api/payments/toss/prepare충전 금액로그인, 금액 옵션, orderId 형식, idempotencyKey를 생성하고 Toss 결제창에 넘길 payload를 반환합니다.필요 시 wallet_transaction에 pending 충전 row를 먼저 남깁니다.
/api/payments/toss/confirmpaymentKey, orderId, amount요청 금액과 주문 주체를 검증한 뒤 Toss /v1/payments/confirm을 호출합니다. 승인 상태가 DONE일 때만 지갑 반영 RPC를 호출합니다.confirm_wallet_charge로 payment_key, order_id, idempotency_key, balance_after를 저장합니다.
/api/payments/toss/webhookToss 이벤트 payload서명 검증 후 결제 실패, 취소, 승인 지연을 idempotency 기준으로 보정합니다.이미 성공 처리된 충전은 중복 반영하지 않고, 실패·취소는 wallet_transaction_status만 보정합니다.

MVP 제외와 보류

현재 설계에서 의도적으로 빼거나 축소한 항목입니다.

항목결정이유
creator_channel제외1유저 1라이브 채널이면 user.id로 충분합니다. 공개 채널 홈과 게시판은 별도 community_* 테이블로 원격 DB에 적용되어 있으나 MVP 라우터에서는 후속 범위입니다.
live_viewer_presence보류실시간 접속자 정확도는 구현 단계에서 Realtime presence 또는 캐시로 판단합니다. 현재 DB 초안은 방송 회차 카운터만 둡니다.
live_metric_snapshot보류MVP 통계는 live_broadcast 누적 카운터와 후원 집계로 먼저 처리합니다. 시계열 리포트가 필요해지면 추가합니다.
payment_order별도 테이블 보류Toss Payments 자체는 MVP에 포함하지만, 결제 주문 row는 우선 wallet_transaction의 pending/succeeded 상태와 payment_key, order_id, idempotency_key로 추적합니다. 결제 수단이 늘어나면 별도 테이블로 분리합니다.
Alert 커스텀 템플릿제외고정 템플릿이 MVP 기준입니다. 이미지 업로드, 효과음 업로드, 애니메이션 선택, 금액별 커스텀은 넣지 않습니다.
실제 정산 인증보류정산 화면용 후원 목록과 연도별 요약 RPC는 존재하지만, 실명조회, 계좌 인증, 세무 정보 입력은 아직 DB 범위에 넣지 않습니다.
